# Незакінчене тренування (чернетка в localStorage)

Дата: 2026-08-09

## Проблема

`WorkoutSessionEditor` тримає весь `DraftWorkout` виключно в React-стейті — до натискання «Зберегти» дані не персистяться ніде. Будь-який вихід зі сторінки стирає введене: свайп «назад», перемикання вкладки в `TabBar`, перезавантаження PWA, вбивство застосунку системою.

Найболючіший сценарій: юзер відкриває «+ Нове тренування», тапає шаблон (`applyRoutine` підтягує 5–6 вправ), починає заповнювати ваги — і відволікається. Повернувшись, бачить порожню форму й мусить набирати все спочатку.

## Рішення

Чернетка незбереженого тренування живе в `localStorage`. Одночасно існує максимум одна. Вкладка «Тренування» показує її картку, а вхід у редактор пропонує продовжити або почати нове.

### Межі фічі

- Тільки створення нового тренування (`workoutId === null`). Режим редагування вже збереженої сесії не чіпаємо: там дані є в БД, втратити можна лише правки, і правило «максимум одна чернетка» від цього лишається простим.
- Тільки `localStorage`. Без синхронізації між пристроями, без міграцій БД, без мережевих запитів на автозбереження.
- Без TTL. Чернетка зникає лише після успішного збереження або явного «Почати нове» / «Відкинути».

## Дані

Новий файл `src/lib/workout-draft.ts`. Один ключ `aura-workout-draft`:

```ts
interface StoredDraft {
  v: 1;              // версія формату
  userId: string;    // чия чернетка
  savedAt: string;   // ISO — джерело для «від 12 серпня»
  draft: DraftWorkout;
}
```

`userId` обов'язковий: `draft.routineId` і `draft.exercises[].exerciseId` — це id рядків з `routines` / `exercises` конкретного користувача. Якщо на одному пристрої перелогінитись, чужа чернетка при збереженні дасть помилку FK або тихо привʼяже сесію до чужої вправи. При незбігу `userId` чернетка ігнорується і чиститься.

### Чисті функції

`isDraftMeaningful(draft: DraftWorkout): boolean` — поріг «змістовної зміни». `true`, якщо виконано хоч що-небудь із:

- `routineId !== null` (обрано шаблон);
- будь-яка вправа має непорожній `name.trim()`;
- будь-який підхід має `weight !== null` або `reps !== null`;
- `note.trim()` непорожній.

Зміна самої лише дати не рахується — інакше кожне відкриття редактора з наступним виходом лишало б сміттєве «незакінчене».

`serializeDraft(draft, userId, now): string` — JSON зі `StoredDraft`.

`parseDraft(raw: string | null, userId: string): DraftWorkout | null` — повертає `null` за будь-якої з умов: `raw` порожній, JSON невалідний, `v !== 1`, `userId` не збігається, форма обʼєкта не відповідає `DraftWorkout` (немає масиву `exercises`, немає `date` тощо). Зіпсований `localStorage` не має ламати сторінку.

При успішному розборі функція **перегенеровує `exercise.key`** (`restored-0`, `restored-1`, …). `key` — це локальний React-ключ, який у `workouts.ts` видає лічильник `keySeq`, що обнуляється щосесії. Ключі зі старої сесії не мають шансу перетнутися з новими, і покладатись тут на випадковість `Date.now()` не варто.

### Доступ до сховища

Тонкі обгортки в тому ж файлі: `readDraft(userId)`, `writeDraft(draft, userId)`, `clearDraft()`. Кожна — у `try/catch`. У приватному режимі Safari `setItem` кидає `QuotaExceededError`; фіча має тихо вимкнутись, а редактор — працювати як раніше.

## Автозбереження

У `WorkoutSessionEditor`, лише коли `workoutId === null`, `loading === false` і `decision !== "pending"`: `useEffect` на `draft` з дебаунсом ~400 мс.

- `isDraftMeaningful(draft)` → `writeDraft`.
- інакше → `clearDraft()`. Юзер стер усе назад до порожнього — незакінченого більше нема.

Окремий прапорець «форма брудна» не потрібен: початковий `EMPTY_DRAFT` не проходить поріг, тож перший рендер нічого не пише.

Після успішного `saveWorkout` — `clearDraft()` перед `router.push("/workouts")`.

## Відновлення

Діалог живе в редакторі `/workouts/new`, а не на кнопці вкладки. На вкладці його можна обійти — перезавантаження PWA прямо на `/workouts/new`, кнопка «назад», відкриття з історії — і юзер мовчки отримає порожню форму при живій чернетці. У редакторі перевірка одна на всі входи.

Стан `decision: "pending" | "resume" | "fresh"`, актуальний тільки для `workoutId === null`. У режимі редагування — одразу `"fresh"`.

На маунті (після того, як відомий `uid`) читаємо чернетку:

- є → `decision = "pending"`, показуємо `DraftResumeSheet` поверх редактора;
- нема → `decision = "fresh"`.

Дії в шіті:

- **Продовжити** → `setDraft(stored)`, `decision = "resume"`;
- **Почати нове** → `clearDraft()`, `decision = "fresh"`;
- **Скасувати** → `router.back()`, чернетка лишається недоторканою.

```
┌────────────────────────────────┐
│ ‹  Нове тренування             │
│                                │
│   ░░░░░░░░░░░░░░░░░░░░░░░░░░   │
├────────────────────────────────┤
│  Незакінчене тренування        │
│  Ноги · 3 вправи · 12 серпня   │
│                                │
│  [        Продовжити        ]  │
│  [ Почати нове ]   Скасувати   │
└────────────────────────────────┘
```

Будується на наявному примітиві `Sheet` з `src/components/ui.tsx` (`open` / `onClose` / `title` / `subtitle`). `onClose` = «Скасувати».

## Картка на вкладці «Тренування»

`UnfinishedWorkoutCard` — акцентна картка одразу під кнопкою «+ Нове тренування»:

```
[ + Нове тренування ]

┌ Незакінчене тренування ────────────┐
│ Ноги · 3 вправи · 12 серп        › │
│                          Відкинути │
└────────────────────────────────────┘
```

Тап по картці веде на `/workouts/new` (де спрацює шіт відновлення). «Відкинути» викликає `clearDraft()` і ховає картку без переходу.

Читання — у `useEffect`, не під час рендера: `localStorage` недоступний на сервері, і читання в тілі компонента дало б розбіжність гідрації. Читаємо після того, як сторінка дізналась `uid` (він уже є в стейті `WorkoutsPage`), бо `readDraft` звіряє власника.

Картка показується і тоді, коли історія порожня — над `EmptyState`. Умова `items.length === 0` в `app/(app)/workouts/page.tsx` зараз віддає `EmptyState` замість усього блоку; картку треба винести з-під цієї гілки.

Після збереження тренування редактор робить `router.push("/workouts")`, сторінка перемонтовується, `useEffect` перечитує сховище — картка зникає сама.

## Помилки й крайні випадки

| Ситуація | Поведінка |
|---|---|
| `localStorage` недоступний або квота вичерпана | Усі операції ковтають виняток. Фіча вимикається, редактор працює як раніше. |
| Зіпсований JSON або чужа версія | `parseDraft` → `null`, ключ чиститься. |
| Чернетка іншого користувача на спільному пристрої | `userId` не збігається → `null`, ключ чиститься. |
| Юзер стер усе введене до порожньої форми | Автозбереження викликає `clearDraft()`. |
| Шаблон, з якого зроблено чернетку, видалено | Чернетка відновлюється як є: назви вправ у ній уже матеріалізовані, а `routineId` при збереженні дасть FK-помилку. Тому при відновленні `routineId` звіряється зі списком завантажених `routines`; якщо такого немає — обнуляється. |

## Тести

Vitest на чисту логіку (за конвенцією проєкту UI перевіряється typecheck / lint / build і вручну):

`isDraftMeaningful`:
- порожній `EMPTY_DRAFT` → `false`;
- змінена лише дата → `false`;
- `routineId` задано → `true`;
- назва вправи задана → `true`;
- підхід із вагою без повторів → `true`;
- підхід із повторами без ваги → `true`;
- непорожня нотатка → `true`.

`parseDraft`:
- валідний payload → `DraftWorkout` з тими самими даними;
- `v: 0` → `null`;
- чужий `userId` → `null`;
- невалідний JSON → `null`;
- `null` на вході → `null`;
- `exercises` не масив → `null`;
- ключі вправ перегенеровано й унікальні в межах масиву.
