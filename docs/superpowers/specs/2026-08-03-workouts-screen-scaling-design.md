# Масштабування екрана «Тренування»

Дата: 2026-08-03

## Проблема

Екран `/workouts` рендерить увесь архів тренувань і всі вправи одразу:

- `loadWorkoutsWithSets` тягне всі тренування разом з усіма сетами одним запитом. За сотень сесій це десятки тисяч рядків на кожен захід на екран.
- Кожна сесія — окрема картка на ~76px. Секція «Прогрес» живе під списком, тож щоб її побачити, треба проскролити весь архів.
- Селектор вправи в «Прогресі» — плаский `flex-wrap` чіпів по всіх використаних вправах. За 50+ вправ це кілька екранів чіпів над графіком.

Цільовий масштаб: кілька сотень сесій, 50+ вправ.

## Рішення

### Порядок блоків

```
Тренування                    Шаблони
[ + Нове тренування ]

┌ Прогрес по вправі ─────────────────┐
│ [ Болгарські випади            ▾ ] │
│ [ Вага ][ 1ПМ ]                    │
│  графік                            │
│  Макс. вага  10 кг          ↑2.0   │
│  28 липня vs 21 липня              │
└────────────────────────────────────┘

Історія
┌ Серпень 2026 · 8 сесій · 62 т ─────┐
│ 2  нд   Сідниці           6 вправ ›│
│ 31 пт   Верх              5 вправ ›│
└────────────────────────────────────┘
       [ Показати ще ]
```

Прогрес переїжджає над списком: це те, заради чого заходять на екран, а архів — довідка нижче. Заголовок-`h2` «Прогрес» зникає (картка вже підписана «Прогрес по вправі»), натомість з'являється заголовок «Історія» над списком.

### Селектор вправи — `ExercisePicker`

Чіп-хмару замінює тригер на всю ширину, стилізований як `Input` (`rounded-[15px]`, `border-primary-light`): ліворуч назва обраної вправи, праворуч шеврон.

Тап відкриває наявний примітив `Sheet` із заголовком «Вправа»:

- поле пошуку (`Input`) зверху, **без** `autoFocus` — щоб на мобільному не вистрибувала клавіатура;
- список зі скролом `max-h-[55vh] overflow-y-auto`. Обмеження висоти живе в консьюмері — примітив `Sheet` не змінюється;
- групування: спершу «Нещодавні» (5 вправ за спаданням дати останнього використання), далі групи м'язів у порядку `MUSCLE_GROUPS`, усередині груп — за алфавітом. Вправи з `muscle_group = null` потрапляють у «інше»;
- під час пошуку групування ховається, показується плаский відфільтрований список. Порівняння підрядка через `toLocaleLowerCase("uk")`;
- рядок = назва вправи + галочка на обраній; тап вибирає вправу і закриває панель;
- нуль результатів пошуку → «Нічого не знайшли».

Джерело списку — вправи, що реально трапляються в сесіях (як і зараз), але з окремого запиту, а не з повного архіву.

### Список сесій

Група = один `Card` на календарний місяць. Хедер: «Серпень 2026» (15px extrabold) + «8 сесій · 62 т» (12px muted). Рядки всередині розділені `border-t border-primary-light`.

Рядок (~56px замість ~76px):

| зона | вміст |
|---|---|
| ліва колонка, ~34px | число дати (15px extrabold) + день тижня скорочено (11px muted) |
| середина | назва тренування (14.5px extrabold), під нею «6 вправ» (12px muted) |
| права | шеврон `›` |

Тоннаж у рядку не показується — він є в місячному підсумку, а рядок лишається читабельним без стиснення назви.

**Пагінація — по цілих місяцях.** Клієнт має повний список місячних підсумків, тож знає, які місяці існують. Сторінка = наступні місяці, доки не набереться ≥12 сесій (або доки місяці не скінчаться). Завдяки цьому кожен відрендерений місяць завжди повний: хедер «8 сесій» ніколи не суперечить кількості показаних рядків. Кнопка «Показати ще» (`Button variant="outline"`) з лічильником решти зникає, коли місяці вичерпано.

## Шар даних

`loadWorkoutsWithSets` видаляється — інших споживачів, окрім цього екрана, у нього немає.

### Нові SQL-функції (`supabase/schema.sql`)

Обидві `security invoker` + `stable`, тож наявні RLS-політики діють як для таблиць.

- `workout_month_totals()` → `month_start date, sessions int, tonnage numeric` по всіх місяцях користувача, за спаданням. ~60 рядків навіть за 5 років. Агрегація мусить бути серверною, інакше заради самих лише хедерів довелось би тягнути весь архів.
- `used_exercises()` → `id uuid, name text, muscle_group text, last_used date, sessions int` — лише вправи, що трапляються в сесіях. ~50 рядків; живить `ExercisePicker` і блок «Нещодавні». PostgREST не вміє `distinct`, тому це RPC.

Тоннаж рахується тією ж логікою, що й `setTonnage` на клієнті: за `weight IS NULL` (власна вага) внесок дорівнює повторам, інакше `weight * reps`.

### Запити PostgREST (без нових функцій)

- `loadWorkoutList(sb, uid, from, to)` → `WorkoutListItem[]`. Select `id, date, name, workout_sets(exercise_id)`; кількість вправ рахується як розмір множини `exercise_id`. Числові колонки не тягнуться взагалі, бо рядок їх не показує.
- `loadExerciseSets(sb, uid, exerciseId)` → `ExerciseSet[]` (`date, weight, reps`). Сети однієї вправи з датою тренування, для графіка й порівняння. ~400 рядків на всю історію вправи.

### Чисті функції (`src/lib/workouts.ts`)

- `setTonnage`, `epley1rm`, `bestSet` — без змін.
- `exerciseCount` — без змін; використовується всередині маппера `loadWorkoutList`.
- `workoutTonnage` лишається: екран його більше не викликає (тоннаж рахує сервер), але від нього залежить `routineSeries`.
- `exerciseSeries` і `compareLastTwo` переводяться з `LoadedWorkout[]` на плаский `ExerciseSet[]`. Вони й так першим ділом фільтрували по `exercise_id` — тепер це робить база, а функції групують сети за датою.
- Нові: `groupByMonth` (сесії → місячні групи), `monthLabel` (ISO-місяць → «Серпень 2026»), `pickMonthPage` (список місячних підсумків + курсор → діапазон дат наступної сторінки).
- `routineSeries` лишається як є: в UI не використовується, чіпати його поза межами задачі.

## Стани

- **Завантаження:** `WorkoutsSkeleton` у стилі наявного `DaySkeleton` — заглушка картки прогресу плюс один місячний блок на три рядки. `FullLoader` з цього екрана зникає.
- **Довантаження сторінки:** `loading` на самій кнопці «Показати ще»; уже показані місяці не перемальовуються.
- **Порожньо:** наявний `EmptyState` без змін. Блок прогресу не рендериться, коли `used_exercises` порожній.
- **Помилка:** `ErrorBanner` зверху. Помилка довантаження не вбиває вже показане — банер під списком, кнопка лишається для повтору.

## Тестування

Vitest покриває лише чисту логіку — за конвенцією проєкту.

- Оновити наявні тести `exerciseSeries` і `compareLastTwo` під плаский вхід `ExerciseSet[]`.
- Нові тести на `groupByMonth`, `monthLabel`, `pickMonthPage` — зокрема межа місяця, порожні місяці між сесіями та вичерпання списку.
- UI перевіряється `npm run typecheck`, `npm run lint`, `npm run build` і ручною перевіркою на мобільній ширині.

## Поза межами

- Віртуалізація списку. Пагінація по місяцях тримає DOM у десятках рядків — віртуалізація без потреби.
- Пошук і фільтри по самих тренуваннях. Місячні групи дають орієнтацію в часі; пошук — окрема задача, якщо знадобиться.
- Перенесення прогресу в «Аналітику».
