# Інсайти: що насправді працює

Дата: 2026-08-16

## Проблема

Застосунок накопичує щоденник, тренування й цикл, але ніде не відповідає на головне питання трекінгу: «що з того, що я роблю, впливає на вагу?» Користувачка бачить графіки окремо, а звʼязок між ними мусить вгадувати. Ідея «Взаємозв'язки» з огляду розвитку — остання нереалізована L-фіча артефакту.

## Рішення

Нова сторінка `/insights` із вкладкою «Інсайти» в таб-барі (замість «Циклу»; «Цикл» переїжджає в профіль). Три фіксовані питання, кожне — гібридна картка: людський висновок + розгортуваний scatter-графік для деталей.

1. **Ккал ↔ зміна ваги** — чи працює дефіцит.
2. **Кроки ↔ зміна ваги** — чи впливає щоденна активність на темп.
3. **Білок ↔ тоннаж** — чи сильніші тренування в тижні з більшим білком.

Всі три картки видно завжди, кожна в одному з чотирьох чесних станів: «звʼязок є» / «звʼязку не видно — і це теж відповідь» / «тижні надто схожі, щоб порівняти» / «ще збираємо дані». Фіча наслідує філософію `MIN_MEANINGFUL_DIFF` з інсайтів циклу: краще промовчати, ніж видати шум за закономірність.

### Межі фічі

- Тільки три пари вище. Інфраструктура (`analyzePair`) — генерична, наступні пари (зокрема «Догляд ↔ шкіра» з артефакту) додаються конфігом.
- Дані циклу в v1 не використовуються: тижневе усереднення згладжує коливання води, а чесна поправка на фазу — окрема методологічна робота. Обмеження явно назване в примітці «Як це порахувано».
- Без міграцій БД і без нових RPC — два запити повторюють патерни `/cycle/insights`.

## Методологія

### Тижнева агрегація

Вікно аналізу — **останні 26 завершених календарних тижнів** (Пн–Нд): достатньо точок для порівняння, але без даних річної давності, коли звички могли бути іншими. Початок вікна — понеділок 26 тижнів до останньої завершеної неділі, тож усі кошики `weekBuckets` повні (7 днів). Поточний незавершений тиждень не аналізується.

Для кожного тижня:

| Метрика | Агрегат | Тиждень валідний, якщо |
|---|---|---|
| ккал, кроки, білок | середнє по заповнених днях | **≥ 4 з 7 днів** із значенням |
| вага | середнє по зважуваннях | **≥ 3 зважування** |
| тоннаж | сума по всіх тренуваннях тижня | завжди (0 = тиждень без тренувань, це справжній нуль, а не пропуск) |

Формула тоннажу — та сама, що в `/cycle/insights`: `weight == null ? reps : weight * reps` (дзеркалить `set_tonnage()` зі схеми).

### Зміна ваги: причинність зі зсувом на тиждень

Δваги тижня *i* = сер. вага тижня *i+1* − сер. вага тижня *i*. Зʼїдене цього тижня видно на терезах наступного; порівняння «ккал(i) ↔ вага(i) − вага(i−1)» змішувало б причину з наслідком минулого тижня. Пара валідна, якщо вага валідна в обох сусідніх тижнях і драйвер (ккал/кроки) валідний у тижні *i*. Отже, з 26 тижнів виходить максимум 25 точок для вагових пар.

Пара «білок ↔ тоннаж» — без зсуву: обидві метрики того самого тижня.

### Порівняння груп — основний вердикт

Валідні тижні-точки `(x, y)` сортуються за X і діляться по медіані: нижня половина — перші `floor(n/2)`, верхня — останні `floor(n/2)`; при непарному n середня точка відкидається (різкіший контраст між групами). Вердикт «звʼязок є» лише коли пройдено три пороги:

1. **`MIN_WEEKS = 8`** парних точок — інакше стан `collecting` із прогресом («5 з 8 тижнів»).
2. **Контраст за X**: `avgX(верхня) − avgX(нижня)` має перевищувати поріг — якщо всі тижні однакові, порівнювати нема що (стан `no-contrast`):
   - ккал: **≥ 120** (менше — в межах точності підрахунку калорій);
   - кроки: **≥ 1000**;
   - білок: **≥ 10 г**.
3. **Значуща різниця за Y**:
   - Δваги: `|avgY(верхня) − avgY(нижня)| ≥ 0.2 кг/тиж` — нижче лежить типовий шум води навіть після тижневого усереднення;
   - тоннаж: симетрична відносна різниця `|hi − lo| / ((hi + lo) / 2) ≥ 0.12` — той самий дух, що `MIN_MEANINGFUL_DIFF = 12%` у циклі; симетрична форма не ламається, коли нижня група близька до нуля. Якщо обидві групи нульові — знаменник 0, вердикт `no-link`.

Пороги не пройдено (тільки №3) → стан `no-link`: «різниця в межах звичного розкиду». Це показується як повноцінний висновок, а не ховається — «не видно звʼязку» теж відповідь.

### Кореляція — лише ілюстрація

Пірсонів r по всіх точках рахується завжди (null при виродженій дисперсії), але показується тільки в розгорнутих деталях зі словесною шкалою: |r| < 0.3 «слабкий», 0.3–0.6 «помітний», > 0.6 «сильний». Вердикт картки r не визначає — він завжди з порівняння груп. Якщо знак r суперечить знаку групової різниці, нічого не робимо: групова різниця вже пройшла пороги, а r — довідка.

### Напрям звʼязку

Вердикт-заголовок залежить від знаку групової різниці:

| Пара | Очікуваний напрям | Заголовок | Зворотний напрям |
|---|---|---|---|
| ккал ↔ Δваги | більше ккал → повільніше падіння (diff > 0) | «Калорії справді працюють» | «Несподівано: звʼязок зворотний» |
| кроки ↔ Δваги | більше кроків → швидше падіння (diff < 0) | «Кроки прискорюють прогрес» | «Несподівано: звʼязок зворотний» |
| білок ↔ тоннаж | більше білка → більший тоннаж (diff > 0) | «Білок підтримує обʼєм тренувань» | «Несподівано: звʼязок зворотний» |

Зворотний напрям показується чесно, з тим самим текстом чисел — вигадувати пояснення не наша робота, ховати результат тим паче.

## Дані

Один `useEffect`, два запити (патерн `/cycle/insights`):

- `daily_logs`: `date, weight, kcal, steps, protein` за вікно аналізу (~185 днів);
- `workouts`: `date, workout_sets(weight, reps)` за той самий діапазон; тоннаж сумується в `Map<date, number>` на клієнті.

## Чиста логіка: `src/lib/correlations.ts`

```ts
/** Мінімум парних тижнів, щоб порівняння груп щось значило. */
export const MIN_WEEKS = 8;

export interface WeekAgg {
  start: string;            // ISO-понеділок
  kcal: number | null;      // null = менше 4 заповнених днів
  steps: number | null;
  protein: number | null;
  weight: number | null;    // null = менше 3 зважувань
  tonnage: number;          // 0 = тиждень без тренувань
}

export interface DayInput {
  date: string;
  weight: number | null;
  kcal: number | null;
  steps: number | null;
  protein: number | null;
}

/** Кошики мусять бути повними тижнями Пн–Нд. */
export function buildWeekAggs(
  days: DayInput[],
  tonnageByDate: Map<string, number>,
  weeks: WeekBucket[],
): WeekAgg[];

export interface PairPoint { weekStart: string; x: number; y: number; }

/** Точки для вагових пар: x = драйвер тижня i, y = вага(i+1) − вага(i). */
export function deltaWeightPoints(aggs: WeekAgg[], xKey: "kcal" | "steps"): PairPoint[];
/** Точки «білок ↔ тоннаж»: обидві метрики того самого тижня. */
export function tonnagePoints(aggs: WeekAgg[]): PairPoint[];

export interface PairThresholds {
  minXContrast: number;
  /** Абсолютний поріг Y (кг/тиж) або відносний (частка), залежно від yDiffMode. */
  minYDiff: number;
  yDiffMode: "absolute" | "relative";
}

export type PairAnalysis =
  | { state: "collecting"; n: number; needed: number }
  | { state: "no-contrast"; n: number; points: PairPoint[] }
  | { state: "no-link"; n: number; r: number | null; points: PairPoint[] }
  | {
      state: "link";
      n: number;
      r: number | null;
      points: PairPoint[];
      lowX: number; highX: number;   // середні X груп — для тексту «≈1650 проти ≈2100»
      lowY: number; highY: number;
      diff: number;                  // highY − lowY, знак = напрям звʼязку
      medianX: number;               // межа груп — вертикальна лінія на scatter
    };

export function analyzePair(points: PairPoint[], t: PairThresholds): PairAnalysis;

/** Пірсонів r; null, якщо точок < 3 або дисперсія X чи Y нульова. */
export function pearson(points: PairPoint[]): number | null;
```

Конфіг трьох пар (пороги + підписи) живе поряд у тому ж файлі — сторінка лише мапить його на картки.

- Заголовок як на інших сторінках (`text-[22px] font-extrabold`), підзаголовок — `text-muted`.

- Примітка «Як це порахувано» — згорнута картка внизу: тижневі середні, зсув Δваги, пороги, чому «не видно звʼязку» — теж результат, і що коливання циклу згладжені, але не виключені.

### `PairInsightCard`

Розкладка успадковує `InsightCard` з `/cycle/insights` (іконка в тонованому квадраті + заголовок + текст), плюс:

- мета-рядок «N тижнів · останні 6 міс» — маленьким `text-muted`;
- кнопка «Деталі ▾» (тільки в станах `link` і `no-link` — коли є що малювати): розгортає scatter + підпис сили звʼязку;
- тексти станів:
  - `link`: «У тижні з меншими калоріями (≈1650 проти ≈2100) вага падала в середньому на 0,4 кг/тиж швидше.»;
  - `no-link`: «Різниця між тижнями з більшими й меншими калоріями — в межах звичного розкиду. Це теж відповідь: на твоїх даних цей важіль не головний.»;
  - `no-contrast`: «Твої тижні надто схожі за калоріями, щоб порівняти. Так буває при стабільному режимі.»;
  - `collecting`: «Зібрано 5 з 8 тижнів із достатніми даними — висновок зʼявиться, коли буде з чого порівнювати.»

Числа — через наявні `fmt` / `fmtInt` (українська локалізація з комою).

### `ScatterChart`

Новий компонент на TanStack Charts (як решта графіків у `charts.tsx`; нотатки по бібліотеці — в memory `tanstack-charts-notes`):

- точки = тижні; осі: X — метрика-драйвер, Y — Δкг/тиж або тоннаж;
- для вагових пар — горизонтальна нульова лінія (вище нуля = вага росла);
- вертикальна пунктирна лінія `medianX` — межа «менших» і «більших» тижнів, візуально повʼязує scatter із текстом висновку (лише у стані `link`; у `no-link` груп у тексті немає, тож і лінія не малюється);
- висота ~160px, без тултіпів у v1 (тап по точці на мобільному — окрема робота, якої висновок не потребує).

## Навігація

- **`TabBar`**: елемент «Цикл» → `{ href: "/insights", label: "Інсайти" }`, іконка — лампочка (inline SVG у стилі решти іконок). Активність через наявний `startsWith`.
- **Профіль**: наявний `SettingsLink` «Цикл» перенаправляється з `/settings/cycle` на `/cycle`, підзаголовок — «Календар, симптоми та прогнози». Налаштування циклу доступні зі сторінки `/cycle` (лінк уже є) та з `CycleDisabled`.
- Сторінки `/cycle/**` більше не підсвічують жодну вкладку — так само, як `/measurements` і `/goals`.

## Крайні випадки

| Ситуація | Поведінка |
|---|---|
| Немає жодного запису щоденника у вікні | `EmptyState` на всю сторінку, картки не рендеряться. |
| Дірки в логуванні (відпустка) | Тижні з < 4 днями даних невалідні за метрикою; вагова пара вимагає валідної ваги у двох сусідніх тижнях — дірка просто зменшує n. |
| Тиждень без тренувань при заповненому щоденнику | Тоннаж 0 — це справжнє значення, тиждень іде в аналіз пари «білок ↔ тоннаж». |
| Обидві групи тоннажу нульові | Знаменник симетричної різниці 0 → `no-link`. |
| Всі тижні з однаковим X | `no-contrast`; Пірсон також вироджений (null) — узгоджено. |
| Непарна кількість точок | Медіанна точка відкидається з обох груп. |
| Звʼязок є, але напрям неочікуваний | Показується з заголовком «Несподівано: звʼязок зворотний» — без вигаданих пояснень. |
| Цикл вимкнений або не ведеться | Нічого не змінюється — сторінка даних циклу не використовує. |
| Помилка запиту | `ErrorBanner`, як на інших сторінках. |

## Тести

Vitest на чисту логіку (`src/lib/correlations.test.ts`); UI — typecheck / lint / build + вручну, за конвенцією проєкту.

- `buildWeekAggs`: пороги валідності (3/4 зважування, 4/7 днів), тоннаж 0 за замовчуванням, кілька тренувань на день сумуються.
- `deltaWeightPoints`: зсув на тиждень уперед; пара випадає, якщо вага невалідна в будь-якому з двох тижнів або драйвер невалідний.
- `tonnagePoints`: без зсуву; тиждень без білка випадає, без тренувань — ні.
- `analyzePair`: усі чотири стани; медіанний спліт із відкиданням середньої точки; обидва режими порогу Y; межові значення точно на порозі (поріг включно).
- `pearson`: відомий приклад, вироджені випадки → null.
