# Графік частоти догляду за шкірою

**Дата:** 2026-07-28
**Статус:** дизайн затверджено, готовий до планування

## Задача

На сторінці «Аналітика» показати, наскільки часто виконуються окремі доглядові дії
(скраб, крем, гуаша, маска, міуінг, масаж — будь-що, що користувачка додала тегом).

Форма — **dot plot** (punch card chart): рядок на кожен вид догляду, колонка на кожен
день періоду, кольорова крапка на перетині. В один день може бути кілька доглядів —
тоді крапки стоять у різних рядках однієї колонки. Легенда пояснює кольори.

## Джерело даних

Змін у БД **немає**. `daily_logs.care` уже зберігає теги одним рядком через кому
(`"Скраб, Крем"`), а `PresetChips` на головній уже вміє додавати власні теги поверх
пресетів `["Скраб", "Крем", "Гуаша", "Маска"]`.

Сторінка «Аналітика» вже вантажить `daily_logs` за вибраний період — рядки графіка
будуються з них. Додатково потрібен **один запит за всю історію** — тільки для
кольорів (див. наступний розділ):

```
select date, care from daily_logs
where user_id = :uid and care is not null
order by date asc
```

Запит виконується один раз при монтуванні сторінки, не залежить від перемикання
періоду, і повертає лише дві короткі колонки. Якщо він падає — графік не ламається:
мапа кольорів будується з логів самого періоду (кольори тоді можуть змінюватись між
періодами, але дані видно).

## Кольори

### Правило

Колір закріплений **за тегом, а не за його позицією в списку**. Перемикання
тиждень↔місяць чи гортання періодів не має перефарбовувати «Крем» з рожевого в жовтий.

Призначення:

1. Слоти 1–4 намертво закріплені за пресетами в порядку `Скраб, Крем, Гуаша, Маска` —
   незалежно від того, чи користувачка ними колись користувалась.
2. Власні теги отримують наступний вільний слот **у порядку першої появи за всю
   історію**. Минуле не змінюється, тож новий тег ніколи не перефарбовує старі.
3. Теги порівнюються за ключем `trim().toLowerCase()`. Показується написання з
   першої появи (для пресетів — канонічне написання пресету).

### Палітра

Однакова на всіх чотирьох темах: якщо кольори доглядів залежатимуть від теми, вони
стрибатимуть при її зміні. Усі теми світлі з білою поверхнею карток, тож одна
палітра працює скрізь.

| Слот | Hex | Відтінок | Кому дістається |
|------|-----|----------|-----------------|
| 1 | `#2E9155` | зелений | Скраб |
| 2 | `#E4749F` | рожевий | Крем |
| 3 | `#C9A84A` | золотий | Гуаша |
| 4 | `#7B4FB8` | лаванда | Маска |
| 5 | `#50B7FE` | блакитний | 1-й власний тег |
| 6 | `#A9246E` | малиновий | 2-й власний |
| 7 | `#8B5A00` | бронза | 3-й власний |
| 8 | `#1980E8` | синій | 4-й власний |
| — | `#8A8A8A` | сірий | 9-й і далі |

Перевірено `dataviz/scripts/validate_palette.js` (light, поверхня `#ffffff`,
`--pairs all`) — **усі перевірки пройдено**: діапазон світлоти, поріг насиченості,
розділення при дальтонізмі (найгірша пара ΔE 8.3, поріг 8), розділення при
нормальному зорі (найгірша пара ΔE 15.2, поріг 15).

Валідатор дає `WARN` на контраст із білим для трьох слотів (`#E4749F` 2.88,
`#C9A84A` 2.29, `#50B7FE` 2.20 при порозі 3:1). Умова зняття цього попередження —
підпис, що не покладається на колір, — виконана конструкцією графіка: **кожен рядок
має постійно видимий текстовий підпис** тега, плюс є легенда й підказка по тапу.
Колір тут підсилює впізнавання, а не несе його сам.

### Стеля у 8 кольорів

Дев'ять і більше категорій надійно розрізнити кольором неможливо — це властивість
кольору, а не вибір палітри. Тому 9-й і далі тег (за глобальним порядком першої
появи) отримує нейтральний сірий. Оскільки призначення глобальне, стеля теж
глобальна: якщо за всю історію використано 10 тегів, два «останні» будуть сірими
навіть у періоді, де інших тегів мало. Це свідомий обмін заради стабільності —
підпис рядка є завжди, тож нічого не губиться.

## Рендер

Не recharts. Це матриця, а не крива: звичайна CSS-сітка дає точний контроль над
шириною колонок на телефоні, зручні цілі для тапу й нуль ваги в бандлі. У
`charts.tsx` компонент не кладемо — там живуть саме recharts-графіки.

```
 Крем     ●  ●  ●  ●  ●  ●  ●   7
 Скраб    ●        ●        ●    3
 Гуаша       ●     ●     ●       3
 Міуінг   ●  ●     ●  ●  ●       5
          ──────────────────────
          Пн Вт Ср Чт Пт Сб Нд
```

**Сітка:** `grid-template-columns: 68px repeat(N, minmax(0, 1fr)) 22px`, де `N` —
кількість днів у періоді (7 або 28–31). На екрані 390px під колонки днів лишається
близько 240px, тобто ~7.7px на день у місяці — вистачає для крапки 6px із зазором.
Розмір крапки залежить від кількості днів: `N <= 7` → 10px, інакше 6px.

**Рядки:** тільки теги, які трапились у періоді хоча б раз. Сортування — за
кількістю (спадання), при рівності — за порядком першої появи. Підпис зліва,
обрізається трикрапкою. Справа маленьке сіре число — скільки разів за період.

**Дні без догляду:** бліда крапка 3px кольору `--primary-light`, щоб читався ритм
сітки.

**Вісь дат:** для тижня — `Пн…Нд` під кожною колонкою (тиждень починається з
понеділка, як у `periodRange`). Для місяця — числа `1, 5, 10, 15, 20, 25` та
останній день місяця, решта колонок без підпису.

**Легенда:** над сіткою, переноситься на кілька рядків: кружечок кольору + назва
тега, у тому ж порядку, що й рядки.

**Підказка:** тап по крапці показує `14 лип · Гуаша`. Ціль тапу більша за крапку
(вся клітинка сітки).

## Публічний інтерфейс `care.ts`

```ts
export const CARE_PRESETS: string[];              // ["Скраб", "Крем", "Гуаша", "Маска"]
export const CARE_COLORS: string[];               // 8 слотів
export const CARE_FALLBACK_COLOR: string;         // "#8A8A8A"

export interface CareTag { key: string; label: string; color: string; }

/** Глобальна мапа «ключ тега → колір», за порядком першої появи. */
export function buildCareColorMap(
  history: { date: string; care: string | null }[],
): Map<string, CareTag>;

export interface CareRow extends CareTag { count: number; days: boolean[]; }

/** Рядки графіка за період: [startISO, startISO + days). */
export function buildCareMatrix(
  logs: { date: string; care: string | null }[],
  startISO: string,
  days: number,
  colors: Map<string, CareTag>,
): CareRow[];
```

`buildCareMatrix` повертає вже відсортовані рядки; `days` — масив довжиною в
кількість днів періоду, `true` = того дня догляд був. Якщо ключа немає в `colors`,
рядок отримує `CARE_FALLBACK_COLOR` — це страховка, а не робочий шлях: сторінка
завжди будує мапу з даних, які має (повна історія, а при її помилці — логи періоду).

## Тестування

Згідно з конвенцією проєкту: vitest — лише на чисту логіку, UI перевіряється
`typecheck` + `lint` + `build` і руками.

`src/lib/care.test.ts`:

- пресети завжди отримують слоти 1–4, навіть якщо ними не користувались;
- власні теги отримують слоти за порядком першої появи;
- теги нормалізуються за регістром і пробілами (`" крем "` = `"Крем"`);
- додавання нового тега не змінює кольори наявних;
- 9-й тег отримує сірий;
- `buildCareMatrix` рахує кількість, позначає правильні дні, сортує за кількістю;
- теги, відсутні в періоді, у рядки не потрапляють;
- `care: null`, порожній рядок і дубль тега в один день не ламають підрахунок.

Ручна перевірка: сторінка «Аналітика» на тижні й на місяці, з одним тегом і з
кількома, на всіх чотирьох темах, порожній період.
