# Сторінка «Тренування» — дизайн

**Дата:** 2026-07-21
**Застосунок:** aura · wellness tracker (Next.js App Router + Supabase + Recharts + теми)
**Мова інтерфейсу:** українська · mobile-first · RLS (дані лише свого користувача)

## Мета

Вносити силові тренування — вправи, вагу, повтори, підходи. Об'єднувати
вправи в іменовані тренування-шаблони (напр. «Ноги», «Верх»),
відстежувати, коли яке тренування робилось, і бачити прогрес на графіках.

---

## 1. Схема БД (нові таблиці)

Усі таблиці — з `user_id` (крім суто дочірніх `routine_exercises` та
`workout_sets`, де ізоляція успадковується через батька), RLS-політика
`*_all_own` за зразком наявних таблиць, індекси за специфікацією.

### `exercises` — довідник вправ користувача
```
id          uuid pk default gen_random_uuid()
user_id     uuid not null → auth.users on delete cascade
name        text not null
muscle_group text  -- 'ноги'|'спина'|'груди'|'плечі'|'руки'|'кор'|'інше' | null
created_at  timestamptz not null default now()
unique (user_id, lower(name))   -- щоб автопідказка не плодила дублі
```
RLS: `auth.uid() = user_id`. Індекс `exercises_user_idx (user_id)`.

### `routines` — шаблони тренувань
```
id, user_id (→auth.users, cascade), name text not null, created_at
```
RLS: `auth.uid() = user_id`.

### `routine_exercises` — вправи в шаблоні та їх порядок
```
id, routine_id (→routines, cascade), exercise_id (→exercises, cascade),
position int not null
```
RLS: доступ, якщо `routine_id` належить власнику
(`exists (select 1 from routines r where r.id = routine_id and r.user_id = auth.uid())`).
Індекс `routine_exercises_routine_idx (routine_id)`.

### `workouts` — конкретна сесія тренування
```
id, user_id (→auth.users, cascade), date date not null,
routine_id uuid null (→routines, on delete set null),
name text,            -- копія назви на момент сесії
note text, created_at
```
RLS: `auth.uid() = user_id`. **Індекс `workouts_user_date_idx (user_id, date desc)`.**

### `workout_sets` — підходи в межах сесії
```
id, workout_id (→workouts, cascade), exercise_id (→exercises, cascade),
set_number int not null,
weight numeric null,  -- null для вправ з власною вагою
reps int not null,
created_at
```
RLS: доступ, якщо `workout_id` належить власнику (exists-підзапит на `workouts`).
**Індекс `workout_sets_workout_idx (workout_id)`.**

Міграція дописується в кінець `supabase/schema.sql` (файл ідемпотентний:
`create table if not exists`, `drop policy if exists` + `create policy`).

## 2. Маршрути та навігація

### Таб-бар (фінальні 5 вкладок)
`Сьогодні / Аналітика / Тренування / Цілі / Профіль`
- «Заміри» **прибрано** з таб-бару; «Тренування» ставиться на його місце
  (3-я позиція, індекс вправи-гантель).
- 5 іконок комфортно вміщуються на 375px (наявний таб уже мав 5 вкладок),
  тому окрема вкладка «Тіло» з під-вкладками не потрібна.

### Сторінки Тренувань (окремі маршрути — обрано за чистоту й нативний back)
```
/workouts             — список сесій (найновіші зверху) + «+ Нове тренування»
/workouts/new         — редактор нової сесії
/workouts/[id]        — редактор наявної сесії
/workouts/routines    — керування шаблонами (routines)
```

### Заміри тіла (перенесення)
- Уся логіка виноситься в **спільний компонент `MeasurementsSection`**
  (`src/components/MeasurementsSection.tsx`).
- У Профілі (`/settings`) рендериться як **згортувана секція** «Заміри тіла»
  (за замовчуванням згорнута, щоб не перевантажувати екран), з тією ж
  функціональністю: форма (талія/стегна/груди/нога/рука), картки з
  дельтою + спарклайн, графік динаміки, банер-нагадування раз на 2 тижні.
- `/measurements` лишається робочим як **тонка сторінка-обгортка** над тим
  самим компонентом — глибокі посилання/закладки не ламаються.

## 3. Компоненти та типи

### Типи (`src/lib/types.ts`)
`Exercise`, `Routine`, `RoutineExercise`, `Workout`, `WorkoutSet`,
`MuscleGroup` (+ `MUSCLE_GROUPS` довідник з підписами).

Локальні (draft) типи редактора:
```ts
DraftSet   = { weight: number | null; reps: number | null }
DraftExercise = { exerciseId: string | null; name: string; sets: DraftSet[] }
```
(exerciseId=null означає «нова назва» — створиться в довіднику при сейві.)

### Нові переиспользувані компоненти
- **`Collapsible`** (в `ui.tsx`) — заголовок + стрілка, керований стан
  відкриття. Використовується в Профілі для секції замірів.
- **`ExerciseAutocomplete`** — інпут назви вправи з випадним списком
  збігів із `exercises`; вибір наявної підставляє `exerciseId`, довільний
  текст лишає `exerciseId=null` (нова вправа).
- **`SetRow`** — рядок підходу: `NumberField` вага (кг, порожня дозволена)
  + `NumberField` повтори; переиспользует наявний `useDecimalBuffer`
  (кома/крапка вже підтримуються).

### Утиліти (`src/lib/utils.ts`)
```ts
tonnage(sets)      // Σ (weight ?? враховуємо як 0-ваговий) × reps;
                   // якщо weight === null → внесок = reps (власна вага)
epley1rm(w, reps)  // w * (1 + reps/30); для null-ваги → null
bestSet(sets)      // підхід із макс. робочою вагою (для 1ПМ і «макс. вага»)
```
Уточнення тоннажу: для підходу з вагою внесок `weight*reps`; для підходу
без ваги внесок `reps` (тобто «тоннаж» вироджується в суму повторів) —
відповідає вимозі UX «вага порожня → тоннаж = повтори».

## 4. Екрани

### 4.1 `/workouts` — список сесій
- Заголовок «Тренування», кнопка **«+ Нове тренування»**.
- Картки хронологічно (desc): дата (`humanDate`), назва, короткий підсумок
  — к-сть вправ і загальний тоннаж (`Σ вага×повтори`). Тап → `/workouts/[id]`.
- Порожній стан (`EmptyState`) з підказкою почати перше тренування.
- Дані: `workouts` (за датою) + агрегат по `workout_sets` (один запит із
  join або два запити + злиття в пам'яті).

### 4.2 `/workouts/new` та `/workouts/[id]` — редактор сесії
Стан-чернетка в пам'яті, збереження **однією кнопкою «Зберегти»** (обрано):
- **Дата** — інпут date (`todayISO()` за замовчуванням).
- **Шаблон** — `Segmented`/список `routines`: вибір підтягує його вправи
  в чернетку (порожні підходи). Або «вручну».
- **Вправи** (список карток), для кожної:
  - `ExerciseAutocomplete` назви (нова назва → додасться в довідник);
  - список підходів (`SetRow`): вага (кг, може бути порожня) + повтори;
  - **«+ підхід»** — дублює попередній підхід (головний сценарій, робимо
    великою зручною кнопкою); видалити підхід (свайп/×).
  - видалити вправу; змінити порядок (кнопки ↑/↓, mobile-first надійніше
    за drag).
- **«+ додати вправу»** знизу.
- Внизу — `note` (Textarea) і кнопка **«Зберегти»** з `SaveIndicator`.

**Логіка збереження (атомарно-послідовно):**
1. Для кожної draft-вправи без `exerciseId`: upsert у `exercises`
   (`on conflict (user_id, lower(name))`), отримати id.
2. Upsert `workouts` (insert для new / update для `[id]`), взяти `name`
   як обрану назву шаблону або перший непорожній.
3. Замінити набір `workout_sets`: видалити наявні для цього workout,
   вставити з чернетки (`set_number` за порядком, пропускаючи рядки без
   `reps`).
4. Порожні вправи (без жодного валідного підходу) ігноруються.

### 4.3 `/workouts/routines` — керування шаблонами
- Список шаблонів (назва + к-сть вправ). Тап → редагувати.
- Створити шаблон (назва) → додати вправи з довідника (`ExerciseAutocomplete`),
  змінити порядок (↑/↓), видалити вправу, видалити шаблон.
- Зберігає `routines` + `routine_exercises` (position).
- Порожній стан із підказкою.

## 5. Графіки прогресу (Recharts, окрема секція `/workouts` або під-екран)

Розміщення: секція **«Прогрес»** унизу `/workouts` (щоб не плодити
маршрути; список і прогрес — одна сутність).

**A. Прогрес по вправі** — вибір вправи (chips/список), `Segmented`
перемикач **«Вага / Тоннаж / 1ПМ»**:
- *Вага* — макс. робоча вага за сесію (`bestSet.weight`) по датах;
- *Тоннаж* — `Σ вага×повтори` вправи за сесію по датах;
- *1ПМ* — оцінка Еплі `weight×(1+reps/30)` найкращого підходу сесії.
Рендер наявним `MetricLine` (label = `shortDate`, value = метрика).

**B. Прогрес по тренуванню (routine)** — вибір шаблону → графік загального
тоннажу сесій цього шаблону по датах (`MetricLine`).

**C. Порівняння з минулим** — для обраної вправи картка: остання сесія vs
попередня (макс. вага і тоннаж) зі стрілкою ↑↓ і дельтою. Стиль — як
картки дельти в замірах (`computeDelta` / ручна різниця, `text-pos/neg`).

Порожні стани для кожного графіка («мало даних — зроби ще тренування»).

## 6. UX-деталі (наскрізні)
- Числа з комою і крапкою — вже покриває `parseNum`/`useDecimalBuffer`.
- Вага може бути порожня (власна вага) → тоннаж = сума повторів.
- Порожні стани з підказками на кожному екрані.
- Дублювання підходу — головний швидкий сценарій, велика кнопка «+ підхід».
- Кольори/тіні/радіуси — лише наявні токени дизайн-системи; жодних нових
  кольорів. Іконки — інлайн-SVG у стилі наявних.

## 7. Порядок реалізації (етапи, кожен із коротким резюме)
1. **Міграції БД** — нові таблиці + RLS + індекси в `schema.sql`; типи в `types.ts`.
2. **Довідник вправ + шаблони** — `ExerciseAutocomplete`, `/workouts/routines`.
3. **Редактор сесії** — `/workouts/new`, `/workouts/[id]`, `SetRow`, дублювання.
4. **Список сесій** — `/workouts` картки + агрегати.
5. **Графіки A/B/C** — секція «Прогрес».
6. **Навігація + поліш** — таб-бар (5 вкладок), винесення `MeasurementsSection`,
   згортувана секція в Профілі, тонка обгортка `/measurements`.
