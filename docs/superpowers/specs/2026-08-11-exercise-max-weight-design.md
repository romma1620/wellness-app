# Максимальна вага вправи в редакторі тренування

Дата: 2026-08-11

## Проблема

`WorkoutSessionEditor` не показує жодного контексту з історії. Юзер набирає вагу «з голови»: скільки він жав минулого місяця, чи це взагалі прогрес — видно лише на окремому екрані прогресу, куди під час тренування ніхто не ходить.

Найпростіший орієнтир, який закриває більшість цієї потреби, — максимальна вага, яку юзер брав у цій вправі. Він мотивує, дає верхню планку і не потребує жодних нових концепцій.

## Рішення

Під полем назви кожної вправи в редакторі — тонкий рядок із рекордом: `Макс 80 кг × 5 · 12 черв`. Щойно введена вага перевищує рекорд, той самий рядок стає акцентним: `Новий рекорд · +2,5 кг`.

### Межі фічі

- Тільки редактор (`WorkoutSessionEditor`). Список сесій, екран прогресу й `ExercisePicker` не чіпаються.
- Тільки максимальна вага. Без 1ПМ, без тоннажу, без «минулого разу» — це окремі метрики, які вже живуть на екрані прогресу.
- Тільки вправи з вагою. Для вправ із власною вагою (`weight is null`) рекорду ваги не існує, рядок не показується.

## Дані

### RPC `exercise_maxes`

Новий агрегат у `supabase/schema.sql`, поряд із `workout_month_totals` / `used_exercises`:

```sql
create or replace function public.exercise_maxes(p_exclude_workout uuid default null)
returns table (exercise_id uuid, weight numeric, reps integer, achieved_on date)
language sql
stable
security invoker
as $$
  select distinct on (s.exercise_id) s.exercise_id, s.weight, s.reps, w.date
  from public.workout_sets s
  join public.workouts w on w.id = s.workout_id
  where w.user_id = auth.uid()
    and s.weight is not null
    and (p_exclude_workout is null or w.id <> p_exclude_workout)
  order by s.exercise_id, s.weight desc, s.reps desc, w.date desc;
$$;
```

Порядок сортування дзеркалить наявний `bestSet()` у `src/lib/workouts.ts`: макс. вага, тай-брейк — більше повторів. Третій ключ (`w.date desc`) `bestSet()` не має, але тут він потрібен: у полі `achieved_on` має бути детермінована дата, а не випадкова з кількох сесій із однаковими вагою й повторами. Свіжіша дата корисніша — вона показує, що рекорд ще актуальний.

`p_exclude_workout` потрібен у режимі редагування вже збереженої сесії: її підходи вже лежать у базі, і без виключення рекордом вважалося б рівно те, що юзер зараз редагує. Тоді рядок ніколи не міг би перейти в стан «новий рекорд», а після зниження ваги показував би як рекорд значення, яке юзер щойно стер.

Окремий індекс під цей запит поки не потрібен — при поточних обсягах seq scan по `workout_sets` достатньо швидкий. `workout_sets_exercise_idx` тут не рятує: він покриває лише перший ключ сортування (`exercise_id`), а не join з `workouts`, фільтр `weight is not null` чи сортування за `(weight desc, reps desc, date desc)`.

Один запит на весь редактор, а не по вправі: у юзера десятки вправ, і `Promise.all` на маунті все одно чекає на `loadExercises` / `loadRoutines`. Тягнути макс ліниво при виборі вправи означало б N запитів і затримку після кожного тапу — зокрема 6 запитів на застосування шаблону з 6 вправ.

### Клієнт

`src/lib/workouts.ts`:

```ts
/** Найкращий підхід вправи за всю історію. Тільки для вправ із вагою. */
export interface ExerciseMax {
  weight: number;
  reps: number;
  date: string; // YYYY-MM-DD
}
```

`src/lib/workouts-db.ts`:

```ts
export async function loadExerciseMaxes(
  sb: SB,
  excludeWorkoutId: string | null,
): Promise<Map<string, ExerciseMax>>
```

Викликає `sb.rpc("exercise_maxes", { p_exclude_workout: excludeWorkoutId })` і збирає мапу `exercise_id → ExerciseMax`. `weight` приходить із `numeric`, тобто рядком у JSON — приводимо через `Number()`, як це вже робить `loadMonthTotals`.

## Логіка стану рядка

Чиста функція в `src/lib/workouts.ts`:

```ts
export type PrState =
  | { kind: "none" }
  | { kind: "record"; max: ExerciseMax }
  | { kind: "beaten"; delta: number };

export function prState(max: ExerciseMax | null, sets: DraftSet[]): PrState;
```

- `max === null` → `{ kind: "none" }`. Вправа нова, або в ній ніколи не було ваги, або назву ще не привʼязано до довідника (`exerciseId === null`).
- Найбільша введена вага серед `sets` більша за `max.weight` → `{ kind: "beaten", delta }`, де `delta = введена − max.weight`.
- Інакше → `{ kind: "record", max }`. Рівність рекорду — не рекорд.

**У розрахунок ідуть підходи з введеною вагою незалежно від повторів.** Природний порядок набору — вага, потім повтори; вимога заповненого `reps` відкладала б сигнал до кінця рядка й позбавляла б його сенсу. Плата: якщо юзер введе 90 кг і не введе повтори, рядок скаже «новий рекорд», хоча `saveWorkout` такий підхід відкине. Це видно лише всередині незбереженого редактора й зникає при збереженні.

## Рендер

Новий `src/components/workouts/ExerciseMaxLine.tsx` — чисто презентаційний, приймає `max: ExerciseMax | null` і `sets: DraftSet[]`.

Рядок стоїть у картці вправи між блоком назви (`ExerciseAutocomplete` + стрілки ↑↓) і списком підходів. Не в одному рядку з назвою: там уже дві кнопки, і довга назва вправи ламала б розкладку.

```
┌──────────────────────────────────┐
│ [ Жим лежачи          ]  ↑    ↓  │
│ Макс 80 кг × 5 · 12 черв         │
│                                  │
│ 1  [ 75   кг] [ 8    ×]     ✕    │
│ 2  [ 75   кг] [ 8    ×]     ✕    │
│                                  │
│ [+ підхід]        Прибрати вправу│
└──────────────────────────────────┘
```

| `kind` | Текст | Класи |
|---|---|---|
| `record` | `Макс 80 кг × 5 · 12 черв` | `text-[12px] font-semibold text-muted` |
| `beaten` | `Новий рекорд · +2,5 кг` | `text-[12px] font-extrabold text-pos` |
| `none` | нічого не рендериться | — |

Обидва видимі стани — той самий розмір шрифту й та сама висота рядка, тож перехід між ними не зсуває підходи під час набору. Стан `none` рядок не рендерить узагалі: «—» або «немає даних» додали б шуму рівно там, де інформації нема.

Без іконки. У кодбейсі немає жодного емодзі — всі іконки це inline SVG, — а колір `text-pos` і `font-extrabold` уже несуть увесь потрібний акцент.

Форматування: `fmt(weight, 1)` для ваги й дельти (дає `82,5` і `2,5` в українській локалі), `shortDateAbbr(date)` для дати — скорочена назва місяця, а не повна: при 12px повна форма (`12 листопада`) впритул підходить до переносу на 360px екрані, а перехід у стан `beaten` («Новий рекорд · +2,5 кг») тоді зменшив би кількість рядків і зсунув підходи нижче. Дельта з явним `+`.

## Підключення в редакторі

`WorkoutSessionEditor`:

- новий стан `maxes: Map<string, ExerciseMax>`, порожня мапа за замовчуванням;
- `loadExerciseMaxes(supabase, workoutId)` додається в наявний `Promise.all` на маунті — додаткового round-trip у часі немає;
- у картці вправи: `<ExerciseMaxLine max={ex.exerciseId ? maxes.get(ex.exerciseId) ?? null : null} sets={ex.sets} />`.

Мапа читається за `exerciseId`, тож поки юзер друкує нову назву (`exerciseId === null`), рядка немає; щойно він обирає вправу зі списку `ExerciseAutocomplete`, рекорд зʼявляється.

Мапа не перечитується після збереження: редактор одразу робить `router.push("/workouts")` і розмонтовується.

## Крайні випадки

| Ситуація | Поведінка |
|---|---|
| Вправа ще жодного разу не робилася | Рядка немає (`none`). |
| Вправа робилася тільки з власною вагою | Рядка немає — `weight is not null` відсікає такі підходи в RPC. |
| Юзер друкує нову назву, ще не обрану зі списку | Рядка немає: `exerciseId === null`. |
| Редагування збереженої сесії | Її власні підходи виключені з рекорду через `p_exclude_workout`. |
| Введена вага дорівнює рекорду | Стан `record`, не `beaten`. |
| Кілька підходів, рекорд б'є лише один | Береться максимум по картці — рядок один на вправу, не на підхід. |
| RPC впав | Мапа лишається порожньою, рядків немає, редактор працює як раніше. Окремого банера немає: рекорд — довідкова інформація, а не те, заради чого відкрили екран. |
| Та сама вправа додана двома окремими картками в одній сесії | Кожна картка має свій незалежний рядок рекорду — вони можуть суперечити одна одній на екрані (картка A з 90 кг показує «Новий рекорд», картка B з 70 кг — «Макс 80 кг»). Прийнято як є: `prState` навмисно рахується по картці, а агрегація між картками — зайва складність заради рідкісного випадку. |

## Тести

Vitest на чисту логіку (за конвенцією проєкту UI перевіряється typecheck / lint / build і вручну). Доповнюємо `src/lib/workouts.test.ts`.

`prState`:
- `max === null` → `none`;
- усі підходи порожні → `record`;
- введена вага нижча за рекорд → `record`;
- введена вага дорівнює рекорду → `record`;
- введена вага вища → `beaten` з правильною дельтою;
- дельта рахується від найбільшої введеної ваги, а не від останнього підходу;
- підхід із вагою й без повторів усе одно рахується;
- підхід із повторами й без ваги ігнорується.
