# Шаблони листів для OTP-авторизації

Застосунок підтверджує пошту **6-значним кодом**, а не посиланням, тож
шаблони листів у Supabase треба замінити вручну (через дашборд це не
автоматизується SQL-ом).

## Порядок дій

> **Спершу SMTP.** Supabase дозволяє редагувати шаблони листів лише
> проєктам із власним SMTP — на вбудованому email-сервісі форма шаблонів
> заблокована. Тож крок 0: Project Settings → **Auth → SMTP Settings** →
> увімкнути Custom SMTP і вписати дані провайдера (див. розділ про SMTP
> нижче). Після цього стане доступним і редагування шаблонів.

Далі Supabase Dashboard → **Authentication → Emails → Templates**:

1. **Confirm signup** — вставити вміст `confirm-signup.html`.
2. **Reset password** — вставити вміст `reset-password.html`.

Ключова змінна в обох — `{{ .Token }}` (6-значний код). Дефолтні шаблони
використовують `{{ .ConfirmationURL }}` (посилання) — його прибираємо.

## Налаштування Auth

Authentication → **Sign In / Providers → Email**:

- **Confirm email** — увімкнено (інакше signUp одразу повертає сесію і
  екран коду в застосунку не з'являтиметься).
- **Email OTP expiration** — за замовчуванням 3600 с (1 год); текст у
  шаблонах це і каже.

## ⚠️ Власний SMTP — обовʼязковий

Вбудований email-сервіс Supabase не лише шле **~2–4 листи на годину**,
а й не дає редагувати шаблони. Варіанти провайдера:

- **Resend** — free tier 3000 листів/міс (100/день), простий сетап,
  є офіційна інтеграція з Supabase.
- **Brevo** (обраний) — 300 листів/день безкоштовно, шле на будь-які
  адреси без власного домену. Налаштування для Supabase:
  - Host: `smtp-relay.brevo.com`, Port: `587`
  - Username: логін із Brevo → SMTP & API → вкладка SMTP
  - Password: **SMTP key** (генерується там само; це не пароль акаунта
    і не API-ключ)
  - Sender: адреса, підтверджена в Brevo (Senders & IPs → Add sender)
- **Gmail app password** — безкоштовно для особистого використання;
  потрібна 2FA і app password, відправник — твоя Gmail-адреса.

Після підключення SMTP підніми ліміти листів: Authentication →
**Rate Limits** → «Emails sent per hour». Окремо завжди діє ліміт
«не частіше 1 листа на 60 с на адресу» — саме під нього в UI кулдаун
повторної відправки.
